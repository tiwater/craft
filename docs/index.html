Overview

Turning LLM-generated robot code into auditable, crash-recoverable, transactional physical operations

Recent agentic code-as-policies frameworks—including ASPIRE, CaP-X, SimEX, and RAX—demonstrate strong program synthesis and iterative repair in single-arm research environments. However, deploying autonomous code policies in commercial robotic cells (espresso brewing, bagel/oven heating, and shared-arm multi-appliance fulfillment) exposes five operational failure modes that research harnesses leave unresolved: non-idempotent appliance restarts, blurred authority between perception and safety interlocks, self-graded LLM repairs, multi-hour onboarding budgets or multi-second online LLM tails, and sequential single-appliance bottlenecks.

TRAX (Transactional Robot Action Execution) addresses these constraints with a pure-Python-stdlib core that enforces strict three-owner separation (Perception Owner ↔ TRAX Governance ↔ Host Actuation). Online, TRAX runs SHA-256-frozen policies inside a restricted Python AST sandbox backed by an intent-before-dispatch SQLite journal with query-first reconciliation and zero online LLM calls. Offline, TRAX runs task-agnostic public-SDK Active Physical Probing (zero hardcoded physics hints), closed-loop simulator calibration, multi-hypothesis RepairScreener with AST-guided selective subroutine repair, zero-actuation recorded_data shadow gating, decoupled independent acceptance, and contract-drift-aware executable skill toolboxes.

Architecture & Core Mechanisms

Strict separation of perception owner, pure-stdlib TRAX governance core, and host actuation interlocks

1. Frozen AST Sandbox & SQLite Intent-Before-Dispatch Journal: Promoted policies are SHA-256-frozen bundles executed in a restricted Python AST interpreter (blocking imports, exec/eval, and leading-underscore access). Every non-idempotent appliance call (start_coffee_machine, start_oven_heat) persists an intent before dispatch and reconciles ambiguous crashes via host query_action_status rather than blindly retrying.

2. Zero-Leakage Active Physical Probing & Closed-Loop Calibration: Automated tests enforce zero task-specific physics constants in prompts. When failures occur, TRAX runs a budget-capped (+1 sim reset) diagnostic probe strictly over public host SDKs to measure empirical grasp offsets or articulation compliance, and runs bounded simulator calibration when target failures do not reproduce in nominal simulation.

3. Multi-Hypothesis RepairScreener & AST Selective Subroutine Repair: Candidate repairs are AST-preflighted, localized to failing policy subroutines via analyze_policy_subroutines, tracked with negative-attempt memory and adaptive stagnation escape, screened against accumulated RegressionSuite banks, and gated by zero-actuation recorded_data shadow replay plus decoupled independent acceptance.

4. Verified Executable Skill Toolbox: Approved skills store AST-validated helper snippets alongside empirical measured_limits and regression_case_ids, and are automatically invalidated whenever the host SDK contract SHA-256 drifts.

Honest Evidence Boundaries & Limitations

Explicit four-tier provenance discipline — simulation passes are never claimed as physical safety approval

Evidence Tier What Is Verified Today What Is Explicitly NOT Claimed
fixture Deterministic AST sandbox, SHA-256 bundles, SQLite journal reconciliation, 4-layer attribution, rollback drills, 110 passing tests. Does not model physical contact, heat transfer, liquid dynamics, or hardware latency.
simulator MuJoCo 3.3.0 7-DOF Panda café cell, Sim-to-Sim noise/DR transfer, multi-appliance combo locks, zero-leakage Robosuite Panda, optional LIBERO harness (host_state_api). Not hardware qualification; LIBERO host_state_api results are not comparable to raw RGB-D RAX benchmarks.
recorded_data Zero-actuation shadow gating on stale, low-confidence, dual-cup ambiguous, and distractor perception frames (0 false actuations). Does not exercise live actuator dynamics or physical closed-loop disturbance recovery.
physical_robot 0 hardware qualification runs completed in this release; host capability contracts documented for ticos-edge + EvidenceScene integration. No physical coffee/bagel manipulation validation or safety certification claimed; local SQLite journal alone does not prove distributed exactly-once actuation without cooperative host keys.
