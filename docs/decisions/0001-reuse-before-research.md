# Reuse before independent research

2026-11-19. Investigation active; no adoption decision yet.

The operator explicitly accepts using an existing project. CRAFT's existence is
not a required outcome. Valid conclusions: direct adoption, thin host adaptation,
upstream contribution, a domain evaluation suite, or independent research backed
by a demonstrated unmet need. Do not expand the custom runtime before this gate.

Requirements: coffee service, bagel loading/heating/unloading, combined orders;
existing EvidenceScene state remains authoritative. Separate missing appliance
hardware/interfaces from algorithmic gaps. Compare with matched models, input
privileges, action abstraction, budgets and development/held-out partitions.

Stages:
1. Full reading and pinned code/license audit of ASPIRE, ACE-CaP-0, RoboRepair,
   Reliable CaP (NeSyRo) and CaP-X.
2. Smallest viable upstream execution/integration probe; reuse before rewriting.
3. Explicit results distinguishing software fixtures, simulator and physical tests.
4. Adoption decision covering feasibility, maintenance and untested assumptions.
5. Propose independent research only if the evidence demonstrates a real gap.

Current: ASPIRE source checked out at fa00f0ef2bc1d91d594b9aa502c22133c9f538f7;
selected docs/interfaces reviewed; 96 selected core tests passed in isolation.
Unmodified upstream execution preserves selected fields from a live edge scene
snapshot. CaP-X source is pinned and its executor/license inspected. See
`references/notes/evaluation-protocol-audit.md` for evaluation differences and
the proposed matched experiment. Four actual coffee simulator runs now pass:
direct host execution and ASPIRE whole-policy delegation, each with normal and
offset/unknown-receipt conditions. Existing host policy and SDK supply recovery;
these runs do not evaluate ASPIRE learning or prove better success rates.
No model generation or physical-robot trial has been run in this reuse audit.
Full paper reviews, strategy-development comparison and oven capability
validation remain pending.

Current decision tendency (not final): favor upstream development tools plus
the existing edge execution owner. Do not build another general runtime merely
to add tracing, skill memory, preconditions or partial recovery: prior work and
the existing host already cover substantial parts of these functions. A useful
next experiment must test learned policy development or a concrete missing
capability, rather than add more wrappers around a known successful policy.

Development-pipeline inspection additionally found upstream campaign, partition,
skill-verification and promotion support (108 selected pipeline tests pass).
Cafe is not an accepted CLI benchmark family. This is a concrete integration
gap to investigate as an upstream extension, not yet an algorithmic gap.
See `references/notes/aspire-development-pipeline-audit.md`.

The running SDK and simulator dispatch have also been audited for warm-food
tasks; see `host-capability-audit.md`. Visible oven/bagel scene geometry is not
an executable appliance contract. Bagel and combined-order algorithm rankings
are currently unsupported; this limitation applies equally to every candidate.
